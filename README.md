# Wild Workspace v2.7.0

**Wild Workspace** — дружелюбный личный планер для задач, мероприятий, проектов и привычек. Приложение сделано как статический HTML-файл: его можно открыть в современном браузере или опубликовать на GitHub Pages.

## Что нового в v2.7.0

- На чистом первом запуске есть примеры задач, мероприятий и привычек — так проще познакомиться с возможностями приложения. На экране приветствия есть пояснение, что демо-данные можно удалить через **Настройки → Сбросить данные**.
- По умолчанию доступны только два блока: **Учёба** и **Работа**. Остальные пользователь добавляет сам.
- На недельной доске порядок колонок: **Выполнено**, **Перенести**, **Запланировано**, **В работе**. Узкая колонка «Выполнено» завершает задачу при перетаскивании; киберкотик анимированно уносит карточку.
- В заголовке недельной доски есть переключатель **Доска / Список** и кнопка киберкотика.
- Статистика получила адаптивную сетку карточек «Завершение по блокам» и «Проекты / направления»; строки проектов и подписи переносятся на узком экране.
- Привычки заметнее: их можно создать прямо на главной в секции «Неделя → Привычки», настроить название, блок и цель на неделю, отмечать прогресс и редактировать.
- На экранах шириной до 720 px вместо верхних кнопок создания появляется плавающая кнопка «+» внизу. На широких экранах верхние кнопки остаются на месте.
- Логотип W не обрезается; добавлены мини-пасхалки и спокойные анимации.

## Демо-данные и сброс

При первом запуске приложение создаёт примеры задач, мероприятий и привычек. Они предназначены только для знакомства с интерфейсом. Чтобы подготовить приложение для реального пользователя, открой **Настройки → Сбросить данные** и подтверди действие. Сброс очищает локальные задачи, мероприятия, праздники, привычки, блоки и настройки, а также локальные вложения, после чего открывает приветствие заново. После такого сброса демонстрационные записи автоматически не восстанавливаются.

Если включена синхронизация Supabase и пользователь вошёл в аккаунт, приложение также пытается очистить облачную копию текущего рабочего пространства. Учётная запись Supabase при этом не удаляется; если сеть недоступна, удаление облачных данных нужно проверить отдельно.

## Запуск локально

Открой `index.html` в актуальном Chrome, Edge, Firefox или Safari. Сборка и установка пакетов не требуются. Для хранения записей используется localStorage; файловые вложения хранятся отдельно в IndexedDB. JSON-резервная копия включает данные и метаданные вложений, но не включает бинарное содержимое файлов.

## Публикация на GitHub Pages

1. Создай репозиторий GitHub.
2. Загрузи содержимое этой папки **в корень репозитория**: `index.html`, `.nojekyll`, `README.md`, `BUG-TRACKING.md` и, если нужно облачное хранилище, `supabase-setup.sql`.
3. В репозитории открой **Settings → Pages**.
4. Выбери публикацию из ветки `main` и папку `/ (root)`, затем сохрани настройки.
5. Открой URL, который покажет GitHub Pages.

Сам архив не выполняет публикацию в аккаунте GitHub автоматически.

## Необязательная синхронизация Supabase

Для аккаунтов и синхронизации можно настроить Supabase:

1. Создай проект Supabase.
2. Выполни `supabase-setup.sql` в SQL Editor.
3. Введи URL проекта и публичный ключ в настройках приложения.
4. Создай аккаунт или войди.

**Не помещай `service_role` key в клиентский HTML.** Используй только публичный ключ и правила Row Level Security. Функции облака требуют настройки и проверки в собственном проекте.

## Календарь

Встроенного Google Calendar API и онлайн-OAuth-подключения нет. Можно скачать `.ics` в настройках и вручную импортировать этот файл в совместимое приложение календаря.
