# Wild Workspace v2.6.0

Личный планер на одном HTML-файле. Интерфейс и основные данные работают локально в браузере; при желании можно настроить синхронизацию и приватное хранение вложений через Supabase.

## Что нового в v2.6.0

- Удалена онлайн-интеграция с Google Calendar API. В приложении нет OAuth-подключения к Google и сетевых запросов к Google Calendar. Оставлен только ручной экспорт `.ics`, который пользователь сам импортирует в календарь.
- В форме задачи больше нет связи с мероприятием и отдельного поля статуса. Новая задача создаётся в статусе «Запланировано».
- Время можно добавить в компактной кнопке внутри поля «План»; планируемая дата и дедлайн остаются отдельными значениями.
- Полный сброс очищает задачи, мероприятия, праздники, привычки, пользовательские блоки, локальные вложения, настройки и локальную сессию, затем открывает приветствие для нового пользователя. Начальные демо-задачи и события не загружаются. При активной облачной сессии приложение также пытается записать пустое рабочее пространство в Supabase; учётная запись Supabase при этом не удаляется.
- Выполненные задачи собираются в блоке «Архив» в разделе «Задачи». В архиве отображаются только задачи со статусом «Готово»; их можно вернуть обратно.
- Статистика включает шесть KPI, 14-дневный график выполнения, нагрузку, сроки, статусы, важность, прогресс по блокам и группировку по проектам.
- Добавлена кнопка «Выполнено!» в карточке любой активной задачи, конфетти и киберкот, который анимированно уносит задачу в архив.
- В настройках показывается название продукта и версия `v2.6.0`.

## Запуск локально

Открой `index.html` в современном браузере. Для обычного использования не нужны сборка или установка зависимостей. Шрифты загружаются из Google Fonts; если сеть недоступна, браузер использует системные запасные шрифты.

## Публикация на GitHub Pages

1. Создай репозиторий GitHub.
2. Загрузи в корень репозитория `index.html`, `.nojekyll`, `README.md`, `BUG-TRACKING.md` и, при необходимости, `supabase-setup.sql`.
3. Открой **Settings → Pages**, выбери публикацию из ветки `main`, папку `/ (root)`, и сохрани настройки.
4. После завершения публикации открой URL, который покажет GitHub Pages.

## Данные и сброс

При первом запуске задачи, мероприятия, праздники и привычки пустые. Основные записи и настройки сохраняются в `localStorage`; файлы, добавленные к задаче, хранятся отдельно в IndexedDB браузера. Экспорт JSON сохраняет метаданные вложений, но не бинарное содержимое файла.

**«Сбросить данные» — разрушительное действие.** Оно очищает локальное рабочее пространство и открывает приветственный экран. При активном подключении Supabase приложение дополнительно пытается записать пустую копию данных текущего аккаунта и выполнить выход. Сам аккаунт аутентификации Supabase не удаляется. Если облачный сервис недоступен или вход не выполнен, очищается только локальная копия и появляется предупреждение.

## Необязательная облачная синхронизация

Для аккаунтов и синхронизации через Supabase:

1. Создай проект на Supabase.
2. Открой SQL Editor и выполни `supabase-setup.sql`.
3. В настройках приложения укажи URL проекта и публичный ключ.
4. Создай аккаунт или войди в него.

Не вставляй секретный `service_role` key в клиентское приложение. Используй только публичный ключ и правила Row Level Security из SQL-файла.

## Резервная копия календаря

Экспорт `.ics` работает офлайн и не подключается к Google Calendar. Он создаёт файл с мероприятиями, датами планирования и отдельными дедлайнами; полученный файл можно вручную импортировать в выбранное календарное приложение.
